# SEO and accessibility

## Per-page metadata

`src/components/Seo.tsx` sets, for every route:

- `<title>` (keyword-led, under 60 characters)
- `<meta name="description">` (under 160 characters)
- canonical URL, derived from the route `path`
- Open Graph (`og:title`, `og:description`, `og:type`) and `twitter:card`
- optional JSON-LD passed by the page

Helpers live in `src/lib/seo.ts`. Defaults for the document shell (title, description, viewport)
are in `index.html`.

## Structured data

`ProjectDetail.tsx` emits a `CreativeWork` JSON-LD node per case study (name, description,
author, keywords, dateCreated). The homepage/about surface the `Person` identity. Keep the
author name in sync with `site.name`.

## Semantics

- One `<h1>` per page; section headings step down without skipping levels.
- Landmarks: `<header>`, `<main id="main">`, `<aside>`, `<footer>`.
- Case-study lists use real `<ol>`/`<ul>`, meta grids use `<dl>`, quotes use
  `<figure>`/`<blockquote>`/`<figcaption>`.

## Accessibility guarantees

- "Skip to content" link targeting `#main`.
- Visible `:focus-visible` outlines on all interactive elements.
- 44px minimum touch targets.
- Every image has descriptive `alt` text (workflow screenshots name the project); decorative
  icons are `aria-hidden`.
- Form fields have associated labels, inline error messaging, and an announced, focused success
  state after submission.
- All motion is disabled under `prefers-reduced-motion`.

## Performance

- Route-level code splitting; homepage is the only eager route.
- WebP screenshots with explicit `width`/`height` so no layout shift occurs.
- `loading="lazy"` on grid images, `loading="eager"` on the case-study hero image.

## When adding a page

1. Render `<Seo>` with a unique title, description, and `path`.
2. Add the route above the catch-all in `App.tsx` and lazy-load it.
3. Add the link to `SiteHeader` and/or `SiteFooter` if it is public-facing.
4. Confirm a single `<h1>` and that `#main` exists for the skip link.

## Phase 1 SEO foundation (technical + entity)

- **Canonical domain**: `https://imawais.engineer` (no www, HTTPS). Single source:
  `SITE_URL` in `src/lib/seo.ts`; `Seo.tsx` builds every canonical and `og:url` from it.
- **Static head** (`index.html`): homepage title, description, canonical, OG/Twitter, and a
  `Person` + `WebSite` JSON-LD graph so crawlers see them before JS runs.
- **Runtime head** (`src/components/Seo.tsx`): unique title/description/canonical per route,
  plus `robots` (`index, follow, max-image-preview:large`, or `noindex, follow` via the
  `noindex` prop), optional `image`, and a single `#page-json-ld` block that is replaced on
  navigation (no duplicate tags).
- **Noindex**: `/terms` and the 404 route only. All portfolio pages stay indexable.
- **Structured data**: homepage emits a `Person` (`#person`, with `alternateName`, `jobTitle`,
  `knowsAbout`, verified `sameAs`) + `WebSite` + `WebPage` graph with stable `@id`s. Each case
  study emits `CreativeWork` authored by `#person`.
- **Sitemap**: generated by `scripts/generate-sitemap.ts` (`predev`/`prebuild`) into
  `public/sitemap.xml` — absolute URLs for `/`, `/projects`, `/about`, `/contact`,
  `/media-kit`, and every project slug. `/terms`, 404s and preview URLs are excluded.
  Re-run happens automatically whenever a project is added.
- **robots.txt**: allows crawlers and rendering assets, advertises
  `https://imawais.engineer/sitemap.xml`.

## Phase 2 SEO — page-to-topic map (on-page keyword architecture)

Each page owns one primary intent. Terms are integrated into real copy (H1, opening
paragraph, section headings, link text, alt text) — never listed, repeated or hidden.

| Page | Primary intent | Supporting terms used naturally |
| --- | --- | --- |
| `/` | Muhammad Awais · AI Automation Engineer | freelance AI Automation Engineer, n8n workflow automation, AI agents, CRM & lead automation, business process automation |
| `/projects` | AI automation projects · n8n automation projects | AI workflow automation, AI agents, CRM automation, lead automation, reporting |
| `/projects/:slug` | The project's own topic (lead qualification, RAG, WhatsApp assistant, reporting…) | project tools and platform only — no forced terms |
| `/about` | About Muhammad Awais · AI Automation Engineer | software engineer, AI developer, full stack developer, n8n expert (secondary identities only) |
| `/contact` | Hire / start an AI automation project | freelance AI Automation Engineer, n8n workflow automation, AI agents |
| `/media-kit` | Muhammad Awais media kit | brand assets, bio, partnerships — no service keywords |

Conventions:

- **Entity consistency**: visible copy always uses "Muhammad Awais" + "AI Automation Engineer".
  Aliases (`imawais`, `Awais`) live only in JSON-LD `alternateName`.
- **Anchor text**: descriptive and semantic — "View all AI automation projects",
  "About Muhammad Awais", "Start an AI automation project".
- **Image alt**: describes the actual image plus its topic, e.g.
  `` `${project.platform} workflow canvas for ${project.name}` `` (ProjectCard,
  FeaturedProjectCard, ProjectDetail) and "Portrait of Muhammad Awais, freelance
  AI Automation Engineer".
- **Site title token**: `site.title` in `src/data/site.ts` is the canonical professional title
  ("AI Automation Engineer — n8n Workflow Automation") used by the footer and media kit.

## Phase 3 — case-study pages (/projects/:slug)

- `src/data/projectSeo.ts` holds per-slug search-intent metadata: primary
  topic, unique title, unique meta description, contextual CTA copy, and
  a short list of genuinely related case studies. All values are derived
  from the existing project data — no invented clients, metrics or dates.
- `ProjectDetail` uses this map for `<title>`, meta description, JSON-LD
  (`CreativeWork` with stable `@id`, `about`, `isPartOf` the site and
  `author`/`creator` pointing at the homepage `#person` entity).
- Page structure answers: what was built → business problem → requirements
  → solution architecture → how the workflow runs → business logic →
  output → outcome → tools & integrations.
- Each page ends with a contextual CTA ("Build a similar … →" → /contact),
  related case studies, a next-project link, and About/Contact links.
- Screenshot alt text uses the real platform plus the project name; the
  caption distinguishes delivered client builds from demonstration builds.
